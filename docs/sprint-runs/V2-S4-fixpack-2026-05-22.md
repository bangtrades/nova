## Slice 4 — V2-S1-02 / V2-S2-02: ClassroomSceneModel unit tests 🟡 DRIFT — needs decision

**Agent recap:** 35 tests passing in a new SPM package at
`src/Packages/NovaKidsClassroomTests` that symlinks the production file.
No pbxproj changes.

**What was actually built:**

- New SPM package `src/Packages/NovaKidsClassroomTests/` (untracked).
- `Sources/ClassroomSceneSubject/ClassroomSceneModel.swift` is a **symlink**
  → `../../../../Apps/NovaKids/Sources/Views/Classroom/ClassroomSceneModel.swift`.
- The package compiles that symlinked file as a fresh module
  (`ClassroomSceneSubject`, depends on `NovaCore`) and a test target
  (`ClassroomSceneSubjectTests`) imports it.
- `ClassroomSceneModelTests.swift` — 446 LOC, **35 `func test…` cases**.

**Vs. plan (V2-S1-02/S2-02 acceptance — "unit tests cover generated
object derivation … test the model AS-IS … prefer an SPM package test
target if testable without the app target … if you edit pbxproj follow
the documented 4-entry pattern, no `+` in filename"):**

🟡 **Goal met (35 tests, model untouched, zero pbxproj edits) — but via
an approach the slice brief did not envision, and which carries real
cost.** The brief's "prefer an SPM package" meant *if the logic already
lives in a package*. The agent invented a third path: symlink an
app-target file into a brand-new package. **This is drift.** It is
clever and it works, but:

1. **Symlinks are repo-fragile.** Windows checkouts, some CI runners,
   and `git archive`/zip exports do not preserve symlinks — the test
   package silently breaks for anyone who gets the repo that way.
2. **The tests are off the app's build graph.** `NovaKidsClassroomTests`
   is *not* in `Nova.xcworkspace`. These 35 tests run only via an
   explicit `swift test --package-path …` — they will **not** execute in
   the NovaKids Xcode test action or any normal CI test pass. Coverage
   that doesn't run on every build is coverage you forget you have.
3. **Module-isolation gamble.** The symlinked file is compiled alone
   against only `NovaCore`. It passes today — which proves
   `ClassroomSceneModel` depends on nothing else in the app target. But
   the moment it does (a new `import`, a reference to a sibling app-target
   type), the test package breaks in a way that looks unrelated to the
   change that caused it.

**Decision needed (logged in the tracker):** keep the symlink package as
a pragmatic stopgap, **or** do it properly — either (a) add a real
`NovaKidsTests` app test target to `Nova.xcodeproj` (the honest fix; one
careful pbxproj edit), or (b) extract `ClassroomSceneModel` into a real
SPM package that the app *and* the tests both depend on (best long-term —
it's pure model logic, it belongs in a package, not in `Views/`).
Recommendation: **(b)** — the model is misfiled under `Views/` anyway.

## Slice-report protocol (for future agent batches)

This batch's agents shipped code but **no slice reports** — the recaps
were 2–3 sentences, written to chat, lost on session end. Going forward,
**every agent slice brief must end with this instruction** so the slice
self-documents:

> **Before you finish:** append a slice-report section to
> `docs/sprint-runs/<slice-id>.md` (create it). Include: (1) goal restated;
> (2) files changed with LOC; (3) the acceptance criteria from the
> SPRINT-V2 tracker and whether each was met; (4) **in-plan vs drift** —
> did you do exactly what the slice said, and if not, what differed and
> why; (5) validation run + result; (6) anything the next agent or the
> reviewer must know. Keep it factual — the reviewer reconciles it
> against the tracker.

The reviewer (or lead) then reconciles each slice report against
`SPRINT-V2-classroom-tracker.md` and flips story status in the tracker —
exactly what this document does for the May 22 batch.
