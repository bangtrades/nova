# Sprint Runs — Rolling Ledger

One row per shipped run — the backward-looking companion to the forward-looking `docs/SPRINT-N-tracker.md` files in the parent directory. Trackers show intent (what I committed to at sprint start); run summaries show truth (what actually landed, with what trade-offs, and what debt retired). This index is the scanner's entry point — sorted newest-first so the top of the table is always the most recent delivery.

Naming: run filenames are `S{sprint}-{slug}.md`. Each file carries a meta block at the top (Run ID, parent sprint, run window, delivery agents, status); the same fields feed the columns below. Run IDs follow `S{sprint}/R{seq}` — single-digit runs use `R01`, multi-story consolidations use ranges like `R03-04-09`.

The ledger is regenerated by hand (or via the `sprint-runner` skill's Operation 4) whenever a new run summary lands. Sort key is the run-window date, ties broken by Run ID descending.
